# Стартовый промпт для Claude Code

Ты работаешь внутри VS Code над новым личным некоммерческим проектом семейного генеалогического сайта.

Сначала полностью прочитай файл `CLAUDE.md` в корне репозитория. Он является главным источником требований и правил. Не игнорируй его и не заменяй требования своими предположениями.

## Цель текущего запуска

Создать надежную основу проекта **«Семейное дерево Огурцовых»** (`ogurtsov-family`) и выполнить только **Этап 0 — проектирование и каркас**. Не пытайся за один запуск реализовать весь сайт.

Сайт в конечном состоянии должен:

- быть публично доступен и индексироваться поисковиками;
- показывать одно большое семейное дерево;
- позволять нажать на человека и открыть справа подробную карточку;
- менять URL при открытии карточки, чтобы ссылкой можно было поделиться;
- иметь отдельную полноценную страницу каждого человека;
- позволять двум заранее созданным редакторам входить по email и паролю;
- позволять редакторам сразу публиковать изменения без модерации;
- позволять добавлять человека и родственников прямо из дерева;
- поддерживать родителей, детей, супругов, несколько браков, разводы, партнерства, биологических, усыновителей, приемных родителей, опекунов, неизвестных родителей и сводные связи;
- показывать даты и места рождения и смерти, родителей, супругов, детей, профессию, образование, краткую биографию, фотографии и скачиваемые файлы;
- поддерживать неточные даты и места;
- искать по имени, фамилии и девичьей фамилии;
- принимать безопасные фотографии и файлы размером до 100 МБ;
- позволять связать одну фотографию или документ с несколькими людьми;
- хранить до 5 ГБ файлов;
- работать на русском языке;
- иметь удобный интерфейс на компьютере, планшете и телефоне;
- обеспечивать переносимость данных и локальное резервное копирование.

## Выбранная техническая основа

Используй решения, зафиксированные в `CLAUDE.md`:

- Next.js 16 App Router;
- TypeScript в строгом режиме;
- Tailwind CSS и локальные компоненты в стиле shadcn/ui;
- Supabase Postgres и Supabase Auth;
- Cloudflare R2 для файлов;
- небольшой Cloudflare Worker для публичной выдачи объектов R2;
- `@xyflow/react` и ELK.js для дерева;
- npm как менеджер пакетов.

Не меняй основной стек без явного согласия пользователя.

## Порядок действий в этом запуске

1. Проверь состояние текущей папки и Git, не удаляя существующие файлы. Если папка еще не является Git-репозиторием, выполни `git init`.
2. Покажи краткий план Этапа 0 максимум из 8 пунктов.
3. Если в папке находятся только `CLAUDE.md`, `START_PROMPT.md` и служебные файлы, создай Next.js-проект через временный каталог и аккуратно перенеси результат в текущий корень, не перезаписывая инструкции. Не вызывай `create-next-app .`, если он отказывается работать в непустой папке. Настрой Next.js 16, TypeScript, App Router, Tailwind CSS, ESLint и npm.
4. Создай согласованную структуру каталогов из `CLAUDE.md`.
5. Добавь и закрепи необходимые зависимости. Не устанавливай лишние библиотеки «на всякий случай».
6. Создай:
   - `README.md` с очень понятной инструкцией для владельца Mac;
   - `.env.example` без секретов;
   - `docs/ARCHITECTURE.md`;
   - `docs/DATA_MODEL.md`;
   - `docs/IMPLEMENTATION_PLAN.md`;
   - `docs/DESIGN_SYSTEM.md` с временной нейтральной темой и пометкой, что дизайн будет уточнен после получения скриншотов;
   - `docs/DECISIONS.md` с принятыми архитектурными решениями;
   - `docs/SECURITY.md`;
   - `docs/BACKUP_AND_RESTORE.md`;
   - пустую папку `docs/design-references/` с инструкцией, куда положить будущие скриншоты.
7. Спроектируй SQL-схему и создай первую миграцию Supabase, но не выполняй ее против удаленного проекта без разрешения пользователя.
8. Добавь небольшой набор вымышленных seed-данных только для локального визуального прототипа. Не используй реальные данные семьи без явного ввода пользователя.
9. Создай базовый публичный экран с заголовком, поиском-заглушкой и временным примером дерева из seed-данных. Пока не реализуй полноценное редактирование, загрузку файлов или боевую авторизацию.
10. Настрой команды:
    - `npm run dev`;
    - `npm run lint`;
    - `npm run typecheck`;
    - `npm run test`;
    - `npm run build`;
    - `npm run preview` или эквивалент, если он действительно нужен текущей архитектуре.
11. Добавь минимальные тесты для утилит форматирования имен и неточных дат.
12. Запусти lint, typecheck, тесты и production build. Исправь все ошибки.
13. В конце остановись. Не переходи к Этапу 1 автоматически.

## Обязательный отчет в конце

Напиши по-русски:

1. что создано;
2. какие команды успешно прошли;
3. какие файлы являются главными;
4. какие внешние аккаунты понадобятся на следующем этапе;
5. какие действия должен выполнить пользователь;
6. точный следующий промпт для Этапа 1.

## Ограничения

- Не выполняй `git push`.
- Не создавай платные ресурсы.
- Не проси и не выводи секретные ключи в чат.
- Не помещай секреты в Git.
- Не запускай разрушительные SQL-команды.
- Не делай публичную регистрацию пользователей.
- Не разрешай загрузку исполняемых или активных веб-файлов.
- Не добавляй функции, прямо исключенные в `CLAUDE.md`.
- Не заменяй реальные проверки типов конструкциями `any`.
- Не оставляй проект с красными тестами или ошибкой сборки.

Начни с чтения `CLAUDE.md`, проверки репозитория и краткого плана Этапа 0.
