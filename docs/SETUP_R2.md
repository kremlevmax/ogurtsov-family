# Настройка Cloudflare R2 и Worker (Этап 4)

Эти шаги выполняет владелец сайта вручную — Claude Code не может
создавать платные ресурсы или вводить платёжные данные за вас
(CLAUDE.md, разделы 5.5 и 21).

## 1. Аккаунт и R2

1. Зайдите на [dash.cloudflare.com](https://dash.cloudflare.com) и войдите
   или зарегистрируйтесь.
2. В боковом меню откройте **R2 Object Storage**. Если R2 ещё не включён,
   Cloudflare может попросить активировать billing на аккаунте — это
   не значит, что с вас спишут деньги при использовании в рамках
   бесплатного лимита, но шаг делаете именно вы.
3. **Create bucket** → назовите бакет `ogurtsov-family-media` (совпадает
   с именем в `workers/media/wrangler.toml`; если назовёте иначе — потом
   поправим файл вместе).

## 2. API-токен для presigned-загрузок

1. В R2 → **Manage R2 API Tokens** → **Create API Token**.
2. Тип токена — **Account API Token**, не User API Token. Account
   token не привязан к вашей личной учётной записи и не сломается,
   если потом что-то изменится в вашем личном доступе к Cloudflare;
   User token предназначен для персональной автоматизации от вашего
   имени, а не для встраивания в приложение.
3. Права: **Object Read & Write**, область — только созданный бакет.
4. Сохраните появившиеся **Access Key ID** и **Secret Access Key** —
   Secret Access Key показывается один раз.
5. Отдельно скопируйте **Account ID** (виден в правой панели дашборда
   R2 или в URL дашборда).

**Про секретность**: `R2_ACCESS_KEY_ID`/`R2_SECRET_ACCESS_KEY` дают
прямой доступ на запись в бакет — обращайтесь с ними как с паролем. Их
можно вписать прямо в `.env.local` самостоятельно, либо продиктовать
мне в чате, чтобы я вписал их за вас (файл остаётся только на вашем
компьютере и никогда не коммитится — см. `.gitignore`). Никому больше
их не передавайте.

## 3. CORS на бакете

Presigned-загрузка идёт напрямую из браузера в R2, поэтому бакету
нужен CORS для локальной разработки и (позже) для боевого домена.
В Cloudflare Dashboard → бакет → **Settings** → **CORS Policy** →
вставьте (пока без боевого домена — добавим, когда он появится):

```json
[
  {
    "AllowedOrigins": ["http://localhost:3000"],
    "AllowedMethods": ["PUT"],
    "AllowedHeaders": ["content-type"],
    "MaxAgeSeconds": 3000
  }
]
```

## 4. Публичный Worker

Worker отдаёт файлы посетителям сайта — не сам бакет напрямую
(CLAUDE.md 5.4).

1. Установите Wrangler CLI, если ещё не установлен — он уже добавлен в
   `devDependencies` проекта, отдельно ставить не нужно.
2. В терминале в корне проекта: `npx wrangler login` — откроется
   браузер для входа в Cloudflare (это делаете вы, не я).
3. Разверните Worker: `npm run worker:deploy`.
4. Wrangler выведет адрес вида `https://ogurtsov-family-media.<ваш-поддомен>.workers.dev`
   — это и есть `NEXT_PUBLIC_MEDIA_BASE_URL`.

Дать Worker'у доступ к бакету не нужно настраивать отдельно — привязка
уже описана в `workers/media/wrangler.toml` (`r2_buckets`).

## 5. Переменные окружения

Заполните (или продиктуйте мне) в `.env.local`:

```
R2_ACCOUNT_ID=<Account ID>
R2_ACCESS_KEY_ID=<Access Key ID>
R2_SECRET_ACCESS_KEY=<Secret Access Key>
R2_BUCKET_NAME=ogurtsov-family-media
NEXT_PUBLIC_MEDIA_BASE_URL=https://ogurtsov-family-media.<ваш-поддомен>.workers.dev
```

После заполнения перезапустите `npm run dev`, чтобы переменные
подхватились (и, если меняли `NEXT_PUBLIC_MEDIA_BASE_URL` или
`R2_ACCOUNT_ID`, пересоберите — эти значения запекаются в
security-заголовки при старте сервера).

## 6. Проверка

1. Войдите как редактор → откройте любого человека → «Редактировать».
2. В разделе «Фото и файлы» загрузите тестовое изображение.
3. Оно должно появиться в списке сразу после загрузки, а на публичной
   странице человека — в галерее.
4. Загрузите любой документ (например, PDF) — должен появиться в
   списке файлов с кнопкой «Скачать».

## Ограничения текущей реализации

- Миниатюры фотографий не генерируются отдельно — для маленького
  семейного архива это не является проблемой производительности; при
  необходимости можно добавить позже (см. `docs/DECISIONS.md`).
- CORS-политику бакета для боевого домена нужно будет добавить при
  развёртывании (Этап 6).
