# Развёртывание (Этап 6)

## Статус

Развёрнуто и проверено вживую: **https://ogurtsov-family.vercel.app**.
Код на GitHub (`github.com/kremlevmax/ogurtsov-family`, через `gh` —
push по HTTPS через `osxkeychain` зависал без объяснимой причины на
этой машине, помогло `gh auth login` + `gh auth setup-git`, см.
`docs/DECISIONS.md`). Ниже — исходная пошаговая инструкция, актуальна
для повторного деплоя (например, второй машины) или отладки.

Стек развёртывания зафиксирован в `CLAUDE.md`, раздел 5.5: Vercel Hobby
(приложение), Supabase Free (база и Auth — тот же проект, что уже
настроен в `docs/SETUP_SUPABASE.md`), Cloudflare R2 + Worker (файлы —
уже настроены в `docs/SETUP_R2.md`).

Все шаги ниже с созданием аккаунтов, платёжных настроек и подключением
GitHub выполняет владелец сайта — Claude Code не создаёт платные
ресурсы, не вводит платёжные данные и не делает `git push` без прямого
разрешения (CLAUDE.md, раздел 21).

## 1. Публикация кода на GitHub

Vercel разворачивает проект из Git-репозитория.

1. Создайте пустой приватный или публичный репозиторий на GitHub
   (публичность репозитория — не то же самое, что публичность сайта;
   можно держать репозиторий приватным, даже если сайт открыт всем).
2. Добавьте remote и запушьте локальный `main`:
   ```bash
   git remote add origin <URL вашего репозитория>
   git push -u origin main
   ```
   Этот шаг делаете вы сами (или явно попросите Claude Code выполнить
   `git push` в чате — по умолчанию агент этого не делает).

## 2. Vercel

1. [vercel.com](https://vercel.com) → **Add New** → **Project** →
   выберите репозиторий.
2. Framework Preset определится как Next.js автоматически. Root
   Directory — корень репозитория (менять не нужно).
3. **Environment Variables** — добавьте те же переменные, что у вас
   заполнены в `.env.local` (список и описание каждой — в
   `.env.example`):

   | Переменная | Значение на проде |
   | --- | --- |
   | `NEXT_PUBLIC_SITE_URL` | реальный домен Vercel-проекта, например `https://ogurtsov-family.vercel.app`, или ваш кастомный домен |
   | `NEXT_PUBLIC_SUPABASE_URL` | как в `.env.local` |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | как в `.env.local` |
   | `SUPABASE_SERVICE_ROLE_KEY` | оставьте пустым — приложению он не нужен, используется только локальными скриптами бэкапа (CLAUDE.md 13) |
   | `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME` | как в `.env.local` |
   | `NEXT_PUBLIC_MEDIA_BASE_URL` | адрес Worker'а из Этапа 4 (`https://….workers.dev`) |

   Секретные значения (ключи, токены) вводите прямо в поля Vercel —
   никогда не коммитьте их в репозиторий.
4. **Deploy**. Первая сборка должна пройти так же, как локальный
   `npm run build`.
5. После первого деплоя скопируйте выданный Vercel-домен и обновите
   переменную `NEXT_PUBLIC_SITE_URL` на этот домен (если на шаге 3 вы
   вписали его заранее правильно — редеплой не нужен). Эта переменная
   используется для `sitemap.xml`, `robots.txt` и абсолютных ссылок в
   метаданных (`app/sitemap.ts`, `app/robots.ts`, `app/layout.tsx`).

## 3. Supabase — обновить для прода

1. Project Settings → **Authentication** → **URL Configuration** →
   добавьте домен Vercel в **Site URL** и **Redirect URLs** (иначе
   вход редакторов будет работать только на `localhost`).
2. Ничего не нужно менять в схеме/RLS — это тот же проект, что и в
   разработке. Отдельный prod-проект не требуется для личного
   некоммерческого сайта такого масштаба.

## 4. Cloudflare R2 — обновить CORS

Бакет уже настроен в Этапе 4 с CORS только на `http://localhost:3000`.
Добавьте туда домен Vercel (Dashboard → R2 → бакет → **Settings** →
**CORS Policy**):

```json
[
  {
    "AllowedOrigins": ["http://localhost:3000", "https://ваш-домен.vercel.app"],
    "AllowedMethods": ["PUT"],
    "AllowedHeaders": ["content-type"],
    "MaxAgeSeconds": 3000
  }
]
```

Без этого шага загрузка фото/файлов в редакторе будет работать локально,
но не на проде (тот же класс проблемы, что уже решали в Этапе 4 —
браузер блокирует прямой `PUT` в R2 с недоверенного origin).

Cloudflare Worker (публичная отдача файлов) уже развёрнут в Этапе 4 и
не привязан к origin — донастраивать не нужно.

## 5. Кастомный домен (когда будет выбран)

Домен пока не выбран (`CLAUDE.md`, раздел 24) — рабочий slug
`ogurtsov-family`. Когда домен появится:

1. Подключите его в Vercel (**Settings** → **Domains**).
2. Обновите `NEXT_PUBLIC_SITE_URL` на новый домен, передеплойте.
3. Добавьте новый домен в CORS-политику R2 (шаг 4) и в Supabase Redirect
   URLs (шаг 3) — старый домен Vercel можно оставить рядом, чтобы не
   сломать уже проиндексированные ссылки, пока Google не переиндексирует
   новый sitemap.

## Прод-чеклист

Перед тем как поделиться ссылкой с семьёй, сверьтесь с Definition of
Done из `CLAUDE.md`, раздел 23, плюс специфичное для деплоя:

- [x] `npm run lint && npm run typecheck && npm run test && npm run build` проходят на последнем коммите;
- [x] сайт открывается на проде без входа, дерево строится, поиск работает;
- [x] оба редактора могут войти на проде (не только на `localhost`) — проверяет пункт 3 выше;
- [x] загрузка фото/документа работает на проде — проверяет пункт 4 выше (потребовалось добавить прод-домен в CORS бакета);
- [x] `https://ogurtsov-family.vercel.app/sitemap.xml` и `/robots.txt` отдают реальный домен, а не `localhost:3000` — проверено вживую;
- [x] `/login` и `/edit/*` не индексируются — проверено вживую (`noindex, nofollow` на `/login`, `/edit` отдаёт 307 без сессии);
- [ ] `SUPABASE_SERVICE_ROLE_KEY` не задан в Vercel (приложению не нужен, см. шаг 2) — **проверьте сами** в Vercel → Settings → Environment Variables, снаружи это не проверить;
- [x] сделан хотя бы один `npm run backup:local` с реальными данными и `npm run backup:verify` его подтвердил — см. `docs/BACKUP_AND_RESTORE.md`;
- [x] `.env.local` не закоммичен (`git status`, `.gitignore` уже это закрывает).

## Особенности бесплатных планов

- **Supabase Free** может «приостановить» проект при долгом отсутствии
  активности — это восстанавливается вручную через Dashboard одним
  кликом, не поломка. Не настраивайте искусственный keepalive-пинг в
  обход этого поведения (CLAUDE.md, раздел 5.5).
- **Cloudflare R2** может потребовать активации billing на аккаунте для
  самого создания бакета, даже если фактическое использование остаётся
  в бесплатном лимите — это разовый шаг, который уже был пройден в
  Этапе 4.
- **Vercel Hobby** ограничен личным некоммерческим использованием —
  соответствует характеру этого проекта (CLAUDE.md, раздел 1).
