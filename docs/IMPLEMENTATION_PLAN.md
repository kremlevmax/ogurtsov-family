# План реализации

Этапы соответствуют `CLAUDE.md`, раздел 22. Каждый этап выполняется
отдельным запуском Claude Code и заканчивается отчётом по-русски;
следующий этап не начинается автоматически.

## Этап 0 — проектирование и каркас (этот запуск)

Готово:

- Next.js 16 + TypeScript strict + Tailwind + ESLint;
- структура каталогов (частично — только то, что нужно этому этапу);
- первая SQL-миграция (`supabase/migrations/0001_init.sql`), не применена;
- вымышленные seed-данные (`features/people/fixtures.ts`, `supabase/seed.sql`);
- рабочий визуальный прототип дерева на `@xyflow/react` + `elkjs`;
- утилиты дат/имён/поиска с unit-тестами;
- lint, typecheck, test, build проходят.

Сознательно не сделано (по инструкции Этапа 0):

- подключение к реальному Supabase-проекту;
- боевая авторизация редакторов;
- полноценная синхронизация URL ↔ открытая карточка человека и мобильный sheet;
- загрузка файлов.

## Этап 3 — полноценное дерево ✅ завершён

- ✅ клик по узлу дерева открывает боковую панель (`components/tree/person-drawer.tsx`)
  вместо перехода на отдельную страницу; дерево остаётся видимым и
  интерактивным (`components/tree/family-tree-explorer.tsx` координирует
  выбор через `window.history.pushState` — маршрут `/` не читает
  `searchParams` на сервере, поэтому смена URL не вызывает повторный
  запрос к Supabase и не сбрасывает pan/zoom);
- ✅ `?person=<uuid>` — URL синхронизируется при выборе и восстанавливает
  открытую панель при загрузке по прямой ссылке;
- ✅ мобильный (`<md`) — панель на весь экран вместо узкой полосы, десктоп
  (`md:`) — панель ~480px, дерево остаётся видимым слева;
- ✅ поиск открывает ту же панель и центрирует/выделяет узел в дереве
  (`FocusOnSelection` в `tree-canvas.tsx`, единый механизм для клика по
  узлу и выбора из поиска);
- ✅ переход между родственниками внутри панели (клик по родителю/ребёнку
  переключает содержимое панели на месте, не закрывая её);
- ✅ быстрые действия редактора перенесены в общий компонент
  `components/people/person-detail-content.tsx`, используемый и панелью,
  и отдельной страницой `/people/[id]` — без дублирования кода;
- ✅ отдельная страница `/people/[id]` сохранена для прямых ссылок и SEO.

Не делалось: виртуализация/производительность для очень больших деревьев

раньше необходимости), можно вернуться при реальной проблеме.

## Этап 4 — R2 media ✅ реализован в коде, ждёт настройки Cloudflare

- ✅ Cloudflare Worker (`workers/media/`) для публичной отдачи файлов —
  GET/HEAD, range-запросы, кэш-заголовки, `Content-Disposition`
  (inline для изображений кроме TIFF, attachment для остального);
- ✅ presigned PUT (`lib/r2/objects.ts`, S3-совместимый API R2) +
  двухэтапная загрузка через `pending_uploads`
  (`server/actions/media.ts`: `presignUploadAction`/`finalizeUploadAction`);
- ✅ allowlist по расширению и MIME на сервере (`lib/validation/media.ts`,
  CLAUDE.md 3.8) + проверка magic bytes для распространённых форматов
  при finalize — не полагаемся на клиентскую проверку;
- ✅ галерея фотографий с полноэкранным просмотром
  (`components/people/media-section.tsx`), список файлов с размером,
  типом и кнопкой «Скачать»;
- ✅ привязка одного файла к нескольким людям (таблица `person_media`),
  профильные фото (переключатель у редактора, unique-индекс в БД);
- ✅ учёт объёма хранилища в `/edit` (сумма `size_bytes`, против ~5 ГБ
  ожидаемого объёма);
- ✅ тесты на allowlist и лимит 100 МиБ (`tests/unit/media-validation.test.ts`).

Не проверено вживую — нужен настоящий Cloudflare-аккаунт с R2 и
развёрнутый Worker (см. `docs/SETUP_R2.md`), которые может создать
только владелец сайта.

Сознательно не сделано: генерация отдельных миниатюр при загрузке
(CLAUDE.md 14) — для объёма личного семейного архива не критично,
загружается оригинал с `loading="lazy"`; можно добавить отдельно, если
станет проблемой на практике (см. `docs/DECISIONS.md`).
