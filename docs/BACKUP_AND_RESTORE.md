# Резервное копирование и восстановление

## Статус

Реализовано на Этапе 6: `npm run backup:local` и `npm run backup:verify`
(`scripts/backup-local.ts`, `scripts/verify-backup.ts`). Ниже — как это
работает по факту; целевое поведение из первоначального плана совпало
с реализацией почти полностью, отличия отмечены явно.

## Зачем это важно

Сохранность семейных данных — приоритет №1 проекта (CLAUDE.md, раздел
2). Переносимость между провайдерами обеспечивается тремя
независимыми механизмами:

1. SQL-миграции в `supabase/migrations/` — сама схема воспроизводима
   на любом Postgres;
2. `npm run backup:local` — полный локальный снимок данных и файлов;
3. опциональный GEDCOM-экспорт (после MVP) — переносимость в другие
   генеалогические программы.

## `npm run backup:local [папка]`

Опциональный аргумент — куда сохранить бэкап (передавайте через `--`:
`npm run backup:local -- /путь/к/папке`); по умолчанию —
`backups/<ISO-метка-времени>/` в корне репозитория (сам каталог
`/backups/` в `.gitignore` — реальные семейные фото туда не коммитятся).

1. Требует явно указанную папку либо использует безопасную папку по
   умолчанию — сделано.
2. Создаёт каталог с меткой времени — сделано.
3. Экспортирует все прикладные таблицы в JSON (`data/*.json`):
   `editors`, `places`, `people`, `relationships`, `media`,
   `person_media`, `site_settings`, `pending_uploads` — сделано, шире
   исходного плана (добавлены `editors`/`pending_uploads`).
4. CSV для `people`, `relationships`, `places`, `media` — сделано
   (`data/csv/*.csv`).
5. Скачивает все объекты R2 в `media/<object_key>`, сохраняя структуру
   ключей — сделано.
6. `manifest.json`: список применённых файлов миграций
   (`supabase/migrations/*.sql`), количество записей по таблицам,
   общий размер и sha256 каждого скачанного файла, список ошибок —
   сделано.
7. Не перезаписывает существующий каталог — завершается с ошибкой и
   кодом выхода 1, если путь уже существует — сделано.
8. Ненулевой код выхода при любой ошибке (не экспортировалась таблица,
   не скачался файл) — сделано.
9. Понятный итог по-русски в конце — сделано.
10. Секреты никогда не пишутся в бэкап или `manifest.json` — сделано;
    сам скрипт при этом **читает** `SUPABASE_SERVICE_ROLE_KEY` из
    `.env.local`, если он задан, чтобы увидеть мягко удалённые записи и
    служебные таблицы (RLS иначе их скрывает от анонимного ключа) — см.
    `docs/DECISIONS.md`, Этап 6. Без service-role key скрипт всё равно
    работает, но бэкап получится частичным — об этом печатается явное
    предупреждение.

## `npm run backup:verify [папка]`

Без аргумента проверяет самый свежий каталог в `backups/`. Читает
`manifest.json`, для каждой таблицы сверяет количество записей в
`data/*.json`, для каждого файла — размер и sha256 на диске против
записанных в манифесте. Ничего не изменяет и не обращается к сети —
сделано в точности по плану.

## `npm run export:gedcom [файл]` (опционально, CLAUDE.md 3.10)

Базовый GEDCOM 5.5.1: люди, родители, супруги, рождение, смерть. По
умолчанию пишет в `exports/ogurtsov-family.ged` (тоже в `.gitignore`).
Известное упрощение — наша модель не хранит пол человека отдельно (роль
матери/отца — на связи, не на персоне), поэтому назначение
GEDCOM-тегов `HUSB`/`WIFE` при неизвестной роли или бездетной паре
делается произвольно (первый — `HUSB`, второй — `WIFE`); подробности —
`docs/DECISIONS.md`, Этап 6.

## Восстановление

1. Поднять новый (или очищенный) Supabase-проект и применить все
   миграции из `supabase/migrations/` по порядку (`supabase db push`
   либо вручную через SQL Editor, как описано в
   `docs/SETUP_SUPABASE.md`).
2. Загрузить JSON из `data/*.json` в соответствующие таблицы (например,
   через Supabase SQL Editor с `insert into … select * from
   json_populate_recordset(...)`, либо любым скриптом-обёрткой над
   `supabase-js` — под конкретный сценарий восстановления пишется
   отдельно, т.к. массовое восстановление делается редко и вручную,
   с явного разрешения владельца, CLAUDE.md раздел 17).
3. Загрузить файлы из `media/` обратно в R2-бакет с теми же ключами
   (сохранена структура `object_key`, включая префикс `media/`).
4. Пересоздать двух editor-пользователей через Supabase Auth и внести
   их `user_id` в таблицу `editors`.
5. Сверить количество записей с `manifest.json`, при необходимости —
   `npm run backup:verify` на восстановленном каталоге, чтобы убедиться,
   что сами файлы бэкапа не повреждены, до того как их заливать обратно.

Перед любой потенциально разрушительной операцией с реальными данными
(миграция, массовое удаление, восстановление поверх существующей базы)
Claude Code обязан заранее подготовить инструкцию по бэкапу и
запросить явное разрешение пользователя (CLAUDE.md, раздел 17).
