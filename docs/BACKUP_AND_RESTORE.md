# Резервное копирование и восстановление

## Статус

Скрипты резервного копирования (`npm run backup:local`,
`npm run backup:verify`) ещё не реализованы — они запланированы на
Этап 6 (CLAUDE.md, раздел 18), после того как появятся реальный
Supabase-проект и R2-бакет, которые нужно бэкапить. Этот документ
описывает целевое поведение заранее, чтобы архитектура остальных
этапов ему не противоречила.

## Зачем это важно

Сохранность семейных данных — приоритет №1 проекта (CLAUDE.md, раздел
2). Переносимость между провайдерами обеспечивается тремя
независимыми механизмами:

1. SQL-миграции в `supabase/migrations/` — сама схема воспроизводима
   на любом Postgres;
2. `npm run backup:local` — полный локальный снимок данных и файлов;
3. опциональный GEDCOM-экспорт (после MVP) — переносимость в другие
   генеалогические программы.

## Целевое поведение `npm run backup:local`

1. Требует явно указанную папку (аргумент/переменная окружения) либо
   использует безопасную папку по умолчанию вне репозитория.
2. Создаёт каталог с меткой времени, например
   `backups/2026-08-14T12-00-00/`.
3. Экспортирует прикладные таблицы (`people`, `relationships`,
   `places`, `media`, `person_media`, `site_settings`) в JSON.
4. Дополнительно создаёт удобные CSV для людей, связей, мест и
   метаданных файлов.
5. Скачивает все объекты R2, сохраняя структуру `object_key`.
6. Создаёт `manifest.json`: версия схемы, количество записей по
   таблицам, общий размер, checksum файлов.
7. Никогда не перезаписывает существующий backup — конфликт имени
   каталога считается ошибкой.
8. Завершается ненулевым кодом при неполном бэкапе (например, если
   часть R2-объектов не скачалась).
9. Печатает понятный итог по-русски.
10. Никогда не включает секреты (ключи, токены) в сам бэкап или в
    `manifest.json`.

## Целевое поведение `npm run backup:verify`

Проверяет ранее созданный `manifest.json`: совпадают ли количество и
checksum файлов с тем, что реально лежит в каталоге бэкапа. Ничего не
изменяет и не обращается к сети.

## Восстановление (черновой план, будет уточнён на Этапе 6)

1. Поднять новый (или очищенный) Supabase-проект и применить все
   миграции из `supabase/migrations/` по порядку.
2. Загрузить JSON/CSV из бэкапа в соответствующие таблицы.
3. Загрузить файлы из бэкапа обратно в R2-бакет, используя те же
   `object_key`.
4. Пересоздать двух editor-пользователей через Supabase Auth и внести
   их `user_id` в таблицу `editors`.
5. Сверить `manifest.json` с фактическим количеством записей.

Перед любой потенциально разрушительной операцией с реальными данными
(миграция, массовое удаление, восстановление поверх существующей базы)
Claude Code обязан заранее подготовить инструкцию по бэкапу и
запросить явное разрешение пользователя (CLAUDE.md, раздел 17).
